# Reject inference

## Why it's needed

`application_train` (now real Kaggle data — see [`01-data-sources.md`](01-data-sources.md))
contains only funded loans. Fitting a scorecard on that alone means fitting on a sample
already filtered by whatever credit policy existed before — the single most common fatal
error in this discipline if ignored.

## The reject pool

Neither the real Kaggle dataset nor any synthetic stand-in for it includes a population of
declined applicants with known characteristics but no observed outcome — a structural gap in
the dataset itself that downloading real data for the accepted population does not close.
`ingest/synthetic_home_credit.py`'s `build_reject_pool` generates one: 8,000 applicants from
the *same* underlying synthetic risk model used to originally stand in for the accepted
population, but with the latent risk factor shifted +0.9 standard deviations — representing
that an existing (unknown-to-us) credit policy already screens out the worse tail, so among
applicants it actually declines, risk is shifted right relative to the funded population.
Their true outcome is generated too, but held in a separate file (`reject_hidden_truth.csv`)
used *only* to validate the technique afterward — something possible only because that side
of the data is simulated.

**Disclosed limitation now that the accepted population is real:** the reject pool's feature
values were generated by the synthetic model, independently of the real accepted population's
actual feature distributions. The technique's *mechanics* are still validly demonstrated
below, but the specific magnitudes (how much the cutoff moves) should be read as illustrative
of the method, not as a production-calibrated correction for this specific real portfolio.

## Method: fuzzy augmentation

1. Score the reject pool with the accept-only model (`scorecard/fit_logistic.py`'s final
   14-characteristic model, fit on real accepted-population data, via the existing WOE bins).
2. Inflate the accept-only model's predicted PD for rejects by 1.5x — the standard
   reject-inference assumption that a rejected applicant is systematically worse than an
   accepted applicant with the same observable score.
3. Duplicate every reject as both a weighted "good" and weighted "bad" record (weights =
   `1 - inflated_pd` and `inflated_pd`), combine with the (unit-weighted, observed-outcome)
   accepted population, and refit.

**Alternatives considered:**
- *Parcelling* would bin rejects into score bands and assign one inferred bad rate per band
  — coarser, but more transparent to a risk committee since the assumption is stated once
  per band. Fuzzy augmentation was chosen because its continuous per-applicant probability
  makes the hidden-truth validation below meaningful at the applicant level.
- *Heckman two-stage* would model the rejection decision and the default outcome jointly,
  correcting selection bias statistically rather than by assumption — more defensible in
  principle, but needs an instrument that shifts acceptance without directly affecting
  default risk, which isn't available here. This is exactly why most industry
  implementations use parcelling or fuzzy augmentation instead, despite Heckman being taught
  first in most textbooks.

## Validation against hidden ground truth (synthetic reject pool only)

| | Value |
|---|---|
| True default rate among rejects | 18.16% |
| Accept-only model's raw predicted rate for rejects | 17.00% (understated) |
| Reject-inference-inflated predicted rate | 25.48% |
| AUC of accept-only score ranking rejects by true outcome | 0.7375 |

The accept-only model (now fit on real data) still *ranks* rejects by risk reasonably well
(AUC 0.74) despite never having seen a reject's true outcome — the understatement is smaller
here (17.0% vs. the true 18.2%) than it was when the accept-only model was itself fit on
synthetic data (13.8% vs. 18.2%), consistent with a real, better-specified model needing a
smaller correction. **A real bank can never run this validation** — a real reject was never
funded, so its true outcome is never observed. This check exists only to make the mechanics
of the technique verifiable in a build where the ground truth happens to be known for one
side of the comparison.

## Quantified impact

Under a fixed policy (decline any applicant with predicted PD > 12%):

| | Approval rate | True bad rate of approved population |
|---|---|---|
| Accept-only model | 79.61% | 5.06% |
| Reject-inference-augmented model | 78.71% | 4.98% |

**Points-scale cutoff shift:** base points (an "average-risk" applicant on every
characteristic) move from 556.5 to 556.0 — a **+0.5 point** tightening. Smaller than the
earlier synthetic-accepts run's +3.1 points, but directionally identical: reject inference
still reveals that the accept-only model was, on the margin, letting through applicants
riskier than its own training data suggested. The smaller magnitude here is itself a useful
data point — it's consistent with the real accept-only model already being better specified
(higher AUC, better-calibrated ranking of the reject pool) than the earlier synthetic-only
version, so there was less bias left for reject inference to correct.

This is the interview-ready number: *on real application data, reject inference shifted our
cutoff by about half a point on the scorecard and reduced approval volume by roughly 1
percentage point — a smaller correction than we saw in development, because the real
accept-only model already ranked the (synthetic) reject population's risk reasonably well on
its own; the technique still moved policy in the expected direction.*
