# Row-Level Security Design

Applies to the Power BI model, filtering on `dim_geography` (the Fannie Mae portfolio's only
geographic dimension — Home Credit's synthetic applicants have no geography field, so RLS
here is demonstrated on the Fannie Mae side of the model).

## Roles

| Role | Filter | Access |
|---|---|---|
| **Regional Risk Manager** | `dim_geography[region] = USERPRINCIPALNAME()`-mapped region (in practice, via a mapping table of user email -> region, since `dim_geography` itself has no user column) | Sees only their assigned region's loans, exposure, defaults, and vintage/roll-rate data — every visual filters through `dim_geography`'s single-direction relationship to `mart_loan_performance`. |
| **Portfolio Head** | No filter (`[1=1]`) | Full access to all regions. |

## Implementation

In Power BI Desktop: Modeling > Manage Roles.

- `Regional Risk Manager` role, DAX filter on `dim_geography`:
  ```
  [region] = LOOKUPVALUE ( UserRegionMap[region], UserRegionMap[email], USERPRINCIPALNAME() )
  ```
  (`UserRegionMap` is a small manually-maintained table: email -> region, not generated by
  this pipeline — a real deployment would source it from an identity/HR system instead of a
  static table.)
- `Portfolio Head` role: no table filter applied.

## Testing evidence

Tested via Modeling > View As Roles in Power BI Desktop:
- Selecting `Regional Risk Manager` with a test email mapped to `"West"` confirmed every
  visual on the Portfolio Overview and Vintage & Roll Rates pages reduced to West-region
  loans only, and the Concentration HHI measure recalculated correctly within that filtered
  context (HHI over states *within* West only, not all 15 states — confirming the measure's
  `REMOVEFILTERS ( dim_geography )` correctly stays scoped to whatever RLS has already
  filtered `dim_geography` down to, rather than escaping the row-level security filter).
- Selecting `Portfolio Head` confirmed all 15 states' data remained visible.

## Note on Home Credit

The Home Credit application-scorecard tables (`mart_application`, `mart_cutoff_frontier`,
etc.) have no geography field in this build, so they carry no RLS in this design. A real
deployment with regional underwriting would need a geography field added to
`mart_application` and RLS extended to that fact table's own dimension relationship.
